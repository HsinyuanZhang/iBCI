# M1 inference-ablation run audit — 2026-09-08

This is a read-only audit of the active `m1_rift_inference_ablations.py` process. The script has no progress writes: it creates `rows` in memory and writes `m1_rift_e3_inference_ablations_v1.json` only after all 25 full held-out-calibration scores and the M10 baseline assertion pass. Therefore, the absent final JSON is expected while work continues and is not evidence of a stalled final write.

The fixed workload is 25 conditions: M10, ZERO, three row-shuffles, and twenty seeded M5/M8 refits. Each condition calls `_ho_score` over the same three held-out sessions with 1,305, 1,295 and 1,281 windows, respectively: 3,881 windows per condition. With scoring batch size 32, this is 123 model forwards per condition and 3,075 forwards across the full run, plus twenty carrier-refit/NWB-read operations. Each forward processes 100-bin, 64-unit contexts with the full RIFT frontend and temporal stack on CPU. A sustained two-core CPU load and a runtime on the order of tens of minutes are therefore consistent with the code path.

There is no data-dependent unbounded loop. The condition loops have fixed finite ranges and `_ho_score` uses finite datasets. The dominant cost is repeated full held-out scoring, not the carrier fits. The only end-stage failure point after this work is the fixed M10 baseline assertion; no partial result is persisted if that assertion or a later write fails.

The existing output records per-condition carrier hashes but not selected trial IDs, per-condition raw carrier vectors, per-condition input NWB hashes, or incremental progress.
