# Cross-session figure schema

`summarize_figure.py --root results/cross_session_v1 --out DIR` is read-only and fail-closed. `program.json` is authoritative: it must enumerate exactly the 33 primary cells, all status `COMPLETED`, with these exact folds: M1 `ses-20120924/26/27/28`, M2 `source7_ext4`, H1 `19250101/08/13/15/19/20`; every fold has Z/B/D at seed 42. Run paths come from `program.json`, not recursive discovery.

It restores task-scoped identity guards before aggregation: M1 validates train/score arm, seed, fold, source-selected receipt, and target-label-selection flag; M2 validates the fixed cell ID `M2-CROSS-SESSION-R50-D4-ZBD-M33-V1` in run metadata, train receipt, and score receipt (its run metadata intentionally has no fold field), plus arm/seed/selection binding; H1 validates nested train metadata and score arm/fold, source-selected epoch, selection flag, 32 curve rows, and 32 checkpoint bindings.

It reads the actual task writers: M1 uses `train_receipt.json` as metadata plus `score_receipt.json`; M2 uses `run_meta.json`, `train_receipt.json`, and `score_receipt.json`; H1 uses nested `train_receipt.json.meta` with schema `h1_lodo_train_receipt_v2`, requires 32 curve rows and 32 EMA checkpoint bindings, and reads `target_score.json`. All tasks require source-selected and final endpoint reports, e24 for M1/M2 and e32 for H1.

Every target-session metric must have an artifact path and recorded SHA-256. NPZ must contain `target`, `prediction`, and at least one query-coordinate array. The script verifies artifact SHA, recomputes R² using canonical `variance_weighted_r2`, and requires receipt agreement within `1e-8`. For each paired Z/B/D task/fold/session and endpoint, target bytes and coordinate bytes must be identical. Missing artifacts, nonfinite values, metadata mismatch, or partial cells aborts without output.

The CSV contains session paths for selected and final endpoints. The figure shows thin paired session paths and bold task means. M1 averages its four outer folds; M2 averages the four EXT4 sessions through its one outer split; H1 first averages sessions within each date then equally averages six dates. H1 sessions remain date-grouped observations, not independent seeds. The figure has no confidence intervals, p values, or significance claims.

The accepted target roster is exact: M1 has only its excluded fold session; M2 has `EXT4_SESSIONS` with `EXT4_EXPECTED_WINDOWS`; H1 has precisely `H1_SESSIONS_BY_DATE[date]`. H1 additionally binds `target_manifest_sha256` to `results/cross_session_v1/h1_prepared_v2/<date>/target/manifest.json` and checks each reported window count against that manifest. Prediction and target arrays must have equal finite shapes. Required strict-increasing integer coordinates are M1 `output_index_query_relative`, M2 `eligible_starts`, and H1 `endpoints`; `prefix_bins` is metadata only. Each selected/final receipt `equal_session_mean` must equal the mean of the independently validated per-session R² values within `1e-10`.

## Paper rendering

The selected-EMA figure is a compact double-column-width (`7.15` inch) three-task layout. Columns are titled only M1, M2, and H1; their subtitle states the actual reporting unit and count: four held-out sessions, four held-out sessions with one source fit per arm, and six held-out dates/13 sessions. The upper row uses gray thin paired session paths, three fixed arm colors at mean nodes (Z gray, B blue, D red), and a black equal-outer-fold mean line. The lower row shows `ΔB=B−Z` and `Δcarrier=D−B`, again with gray paired paths, black mean line, and printed observed mean values. It deliberately has no error bars, confidence intervals, standard deviations, p values, or significance marks. A single footer records seed 42 and source-validation selection, avoiding repeated long titles.

Before the root generates the formal figure, confirm that the full 33-cell program is `COMPLETED`, the collector creates all CSV/JSON/PDF/PNG outputs without relaxing a guard, the PDF is readable at two-column width, the printed values agree with `cross_session_figure_summary.json`, and the H1 column visibly retains its date-level rather than 13-session-level mean interpretation.

The footer is two short centered lines, with an explicit reserved bottom margin: `Seed 42; source-validation EMA selection.` and `Gray: paired sessions; black: equal-fold mean. No CI or significance test.` The H1 six-date aggregation rule remains in the caption/schema rather than the in-figure footer.

The upper row remains source-selected EMA only. In the lower increment row, the source-selected equal-fold mean is a black solid line with colored filled circles. The prespecified fixed-final sensitivity is a black fine dashed line with hollow square mean markers at the same `ΔB` and `Δcarrier` x positions: e24 for M1/M2 and e32 for H1. It does not add final per-session lines, error bars, or statistical annotation. The three-line footer defines these endpoints and retains explicitly reserved lower space.

For overlapping selected/final increment values, the hollow final square is drawn below the selected filled circle (`zorder 3.5` versus `5`) and enlarged to preserve both marker meanings. Footer and printed mean values use 7pt type after bbox verification.
