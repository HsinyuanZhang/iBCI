## 每个消融的输入合同

所有消融均对齐**本 task 的主提交 full recipe**：保持该 task 的训练数据、session roster、reader、时间窗、模型家族、初始化规则、sampler、优化器、EMA、epoch scan、选择规则和 runtime/frontend 约定。不得把一个 task/family 的 recipe 移植为另一个 task/family 的替代物。

`ACTIVITY_ONLY` 保留 activity calibration，但移除行为响应 carrier：

- M1：复用已有独立 B `ACTIVITY_ONLY` 训练；其 `side T` 与 direct `T` 均为零，M10 无标签神经活动仍可形成 activity identity/E0。它不是“完全无 calibration”。
- M2：使用主线同一冻结 encoder，以零 side 在训练前重新 materialize 静态 E0，并令 direct `T=0`；保持原 `RiftConcatDecoder` 及其参数集合，不加入新的 live/trainable encoder。不得保留 FULL E0 内已混入的 carrier。
- H1：必须以零 side 重新熔合 C2 E0，并令 direct `T=0`；不得保留 FULL E0 内已混入的 carrier。

`NONE` 同时移除 activity 与 carrier：`E0=0`、direct `T=0`，side path 也不能接收静态信息。它仍是该 task 的正常 neural decoder，而不是跨 task 的新模型或缩减 recipe。零 identity 不等于 strict zero-shot：所有 profile 的 `IsHeldOutZeroShot=false`，因为 all-24/32 epoch selection 使用带标签的公开 HO 数据。

H1 的原停止决定只作如下有限修订：允许本表的两个 **signed-state baseline 信息消融**，但绝不恢复 H1 NMF3、v4 joint-ridge 新 carrier、fusion grid 或主方法替换。H1 的主方法仍为 signed-state14。
