# Track-B v2 Subject-M paired live launcher

This additive launcher is dry-plan only until two canonical immutable inputs
exist: the paired-real-producer execution addendum and a separately
root-reviewed launcher preflight.  The latter breaks the closure cycle by
binding the final launcher files and the already-sealed producer addendum;
neither authority alone permits target or GPU access.

Each view owns fifteen prospective output pairs: a parent pre-spawn launch
contract, start, source, target, encoder receipt, checkpoint, embedding bundle,
six scores, completion, and terminal.  A global paired completion is the
thirty-first pair.  The launch contract contains only a token hash and freezes
the child argv/environment/CWD/interpreter/preflight before spawn.  Source is a
mandatory independently published receipt and is exact-bound by the encoder,
completion, and terminal chain.

An authorised parent may only launch the exact conda interpreter in a clean
child environment with `PYTHONNOUSERSITE=1`, empty `PYTHONPATH`, and
`CUDA_VISIBLE_DEVICES=1`.  The child compares logical `cuda:0`, UUID, PCI BDF,
driver, Torch and CUDA runtime to the immutable cost receipt, publishes start
before target access, and then executes one independent view.  pMUA cannot
start until both parent and pMUA child reload the immutable successful SUA
source/completion/terminal chain.  At success finalization the launcher reloads
the preflight, requires launch/final/live closure equality, and validates every
cell/upstream/route/V9/TorchMetrics binding before completion.  A nonzero child
exit publishes a canonical failure completion bound to its launch contract and
makes the cell non-reusable.

Private target snapshots are never score receipts.  On success they may be
removed only after target, encoder, embedding, and all six score hashes are
published; on failure the verified 0444 inode is retained for forensic review
and the failure completion prevents reuse.
