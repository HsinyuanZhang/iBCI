## 1. 收敛发现：两条路推到同一个算子

- Grok-2（从 B 出发）：让每个记忆 token 在**出生时**对前 `s` 个已冻结的同层状态做因果读，之后永久冻结；当前 query 仍按 QueryAge16 读全部 W。`s=1` 精确退化为 B。
- Grok-3（从 A 出发）：前 3 层改成**带宽 `b` 的局部因果注意力 + 带内相对位置**，最后一层保留全窗 last-query。因为感受野有限且位置是相对的，每个 token 的各层状态**出生即定**，可精确缓存；H1 时间核约 20× 于 exact-E。

两者是同一件事的两种写法：**局部因果、相对位置、出生冻结的记忆，加当前 bin 的全窗读出**。它就是标准 sliding-window-attention 解码器（Mistral/Longformer 一类）再加一条全局读出，不是新发明，但恰好同时修掉 A 的缓存问题和 B 的无互读问题。

### 1.1 候选定义（工作名 `FW-LocalCausalAge[s]`，最终命名交 Astra）

记 `z_t` 为前端第 t 个 bin 的 256-d token，层 `ℓ=1..4`，记忆状态 `m^ℓ_t`，`m^0_t = z_t`。

记忆路径（出生一次，永久冻结）：

```text
m^ℓ_t = Block^ℓ( q = LN(m^{ℓ-1}_t),
                 K,V = proj(LN(m^{ℓ-1}_{t-s+1..t})),
                 bias = a^ℓ_h(age_within_s) )        # pre-LN attn + residual + FFN
```

只依赖 `t-s+1..t` 这些**已冻结**的上一层状态，因此可缓存；每层只存最近 W 个 token 的 K/V（同现有 `QueryMemoryCache`，键改为 `m^{ℓ-1}` 而非 `z`）。

查询路径（当前 bin T，与现有 `QueryReadBlock` 相同，只是键来自 `m^{ℓ-1}`）：

```text
q^0 = z_T
q^ℓ = Block^ℓ( q = LN(q^{ℓ-1}),
               K,V = cached proj of m^{ℓ-1}_{T-W+1..T},
               bias = age16^ℓ_h over W )
readout(final_norm(q^L))
```

约定：
- `s=1` 时**跳过**记忆路径（`m^ℓ_t := z_t`），此时与 `FW-QueryAge16` 逐字节同算子。这是合同测试，不是口头声明。
- 记忆路径**不得**使用窗口相对正弦 PE；只允许带内相对 age 偏置（或 RoPE-at-read）。否则缓存立刻失效。
- 全局读出的 16 档 age 与 B 保持一致；H1 上 44 bin/档 的粗糙问题另立命名变体，不在第一格混改。
- 记忆块与查询块**共享权重**是默认建议（一个 Transformer，只是历史 token 注意力跨度 `s`、当前 token 跨度 `W`）；分离权重作为消融。二者在 `s=1` 都精确等于 B。

### 1.2 退化与边界

| 设定 | 等于什么 |
|---|---|
| `s=1` | 精确 `FW-QueryAge16` |
| `s=W`，出生冻结 | **不是** A。A 每步重算并让旧 token 被当前窗口重新语境化；这里旧 token 的状态由它自己的过去决定。这是标准 AR KV-cache Transformer，不是滑窗全重算 |
| `s=W` 且每步重算 | 就是 A 的 exact-E，缓存合同消失 |

它保留的是「每个历史 token 出生时读过前 `s` 个 token，且逐层加深（感受野 `1+(s-1)L`）」。它丢掉的是「旧 token 随窗口滑动被重写」。对流式因果解码，前者更自然；是否损失质量，由实验决定。

### 1.3 成本

每步：新 token 过 L 层局部注意力 `O(L·s·d + L·d² + L·d·f)`，加当前 query 读 W `O(L·W·d)`。

- H1 W=700, s=50：约 5 MFLOP/步，对比 exact-E 前三层约 1.9–2.7 GFLOP，时间核 ≈ 400× 少；墙钟会被 5-token 前端主导，预计落到已测「缓存 QueryAge」一档（探针约 7.7 ms）而非 exact-E 的 23.8 ms。
- M2 W=50：时间核本来不主导，端到端 ≈ 1.0×。M2 上的意义是**质量**判别，不是速度。
- M1：B 已 ≈ A，只有 ~1 ms 差距，不需要它。

### 1.4 相邻候选（已排序，不并行开）

| 排序 | 名字 | 与候选的关系 | 何时用 |
|---|---|---|---|
| 1 | `FW-LocalCausalAge[s]`（上文） | 主候选 | 第一格 |
| 2 | 绝对时间对齐分块 `ChunkAge[c]` | 同缓存合同，但 1 s 网格切断跨界笔画 | 若 s-窗实现困难时的替身；不推荐 |
| 3 | 短窗 exact-E(A) + 长窗 B 读出 `HybridDense[s]` | 每步 `O(s²+W)`，短窗 s 个 token 仍重写，不是严格缓存 | 只有当 A ≥ U + 0.015 且 A ≥ B + 0.015 时升级 |

## 2. 提升 `FW-QueryAge16`（Grok-1 结论 + 本文取舍）

### 2.1 不改名就能做的

1. **把 M2 QueryAge 跑完再下结论。** e20 源面 ≈ 同协议 CausalPE 家族对，尚不能说输赢。官方 0.390 是**另一条配方**（S1-COS、非家族）的成品数，不能拿来判 B。
2. **H1 门槛配方对齐。** 现 H1 QueryAge 源门槛**禁用 prefix 与 EMA**，而 M1/M2 都用。这样跑出的 H1 A/B 不是算子对照，是配方对照。建议门槛通过后，formal 对显式声明与 M1/M2 一致的 EMA + prefix；不是悄悄改成员。
3. **蒸馏诊断（可选，M2）。** 以同前端 CausalPE 为教师、B 为学生。若学生追平教师，说明「原始 z 记忆 + 4 步 query」就够，第 1 节候选可不必开；若追不平，就是「独立键读不出历史互读」的最干净证据。这是诊断，不是产品路线。

### 2.2 要新名字才能做的

| 想法 | 每步增量 | 为什么可能补差 | 命名 |
|---|---|---|---|
| 记忆编码器（因果 conv 或出生局部注意力，RF ≥ 64） | +O(k) 或 +O(s) | 唯一合法把历史互读放进键的方式；即第 1 节候选 | 新成员 |
| 细粒度 age（RoPE-at-read / log-age / 64 档） | +4×O(W) 便宜查表 | H1 上 16 档 = 44 bin/档；M1 6 bin/档已够，所以是 H1 尺度问题 | 新成员（冻结禁止同名换 age 规则） |
| 出生对齐慢记忆（每 c 步关闭的 chunk 均值 / 因果 EMA 键） | +4×O(W/c) | 线性长程摘要 | 新成员 |
| 杀：ALiBi 斜率 | — | 现有 16 档可学查表已严格更强 | — |
| 杀：多 query 读出 | ×m | query 不会成为记忆，不产生互读 | — |

**QueryAge 何时能当唯一统一核：** M2 完成后与同协议 CausalPE 差 ≤ 0.01，且 H1 vanilla 与 CausalPE 在同 20,325 bin 差 ≤ 0.02。M1 已满足。若 H1 差 ≥ 0.03，统一核就不是 vanilla B，而是第 1 节候选。

## 3. 大幅降低 `FW-CausalPE4` 运算量

### 3.1 冻结权重、不重训（可直接用于 581973 类成品）

第一轮已列：窗裁剪 `W'`、每 R 步整窗刷新、尾部 k 重算+前缀冻结。本轮补一个**诊断价值**：在 H1 冻结 A 上扫 `W' ∈ {128, 256, 350, 700}`。若 256 ≈ 700，同时回答「700 是否真有用」和「第 1 节候选的 W/s 该取多少」。出厂 Original 的 cold(<699) .956 vs full .963 已暗示好解码器不依赖 14 s 互读。

### 3.2 重训才有的大幅削减

| 方案 | H1 时间核倍数 | 缓存 | 命名 |
|---|---|---|---|
| 局部因果 + 相对位置（= 第 1 节候选） | ~20×（再加缓存 → 数百×） | **有** | 新成员 |
| 两速 token 池化（最近 s 个原 bin + 更早每 p 个池化） | ~5× | 无（除非改成绝对时间发射 + 相对 PE，那就是新位置规则） | 新成员 |
| 注册 H1 W=200（同 PE/掩码/深宽） | ~4.8× | 无 | 同成员，声明 W |
| 深度重分配 C2Q2 | ~1.4× | 无 | 不达标 |
| 前三层 128 宽 | ~2.6× | 无 | 不达标，且削弱本已弱的 H1 |
| 跨层共享 K/V | ~1.1× | 无 | 悄悄滑向 QueryAge，杀 |

结论：若要**重训**才能减算量，池化-A 被第 1 节候选支配（后者同时给出缓存与局部互读）。重训预算应投到候选，不投到池化-A。只有 Astra 坚持保留「滑窗全重算」这一 A 的身份时，注册 `W=200` 才是唯一保身份的削减，且必须在 A 已能学之后作为声明的 W 消融，不能用来绕 H1 学习门槛。

## 4. 建议的第一格实验

不在 H1 开（前端未解，读不出时间核）。不在 M1 开（B ≈ A，预期为空）。

**场地：M2 SMALL W=50，FLAT 单臂三行，同一配方。**

| 行 | 时间核 | 拨盘 |
|---|---|---|
| A | `FW-CausalPE4` | — |
| B | `FW-QueryAge16` ≡ U(s=1) | s=1 |
| U | `FW-LocalCausalAge` | s=50（预算允许再加 s=8） |

配方锁定：seed 42、24 epoch、source-train only、EMA 等会话 R² 在封存 1,011 源 minival 选点、最早 epoch 平局规则。**重要：** 现运行的 M2 QueryAge 是 prefix 配方，家族 CausalPE 对不是。三行必须同配方——要么 A、U 也加 prefix（复用即将完成的 B），要么三行都不加。Astra 决定，但不能混。

合同测试（先于任何质量主张）：`s=1` 与 `FW-QueryAge16` 原生输出差 ≤ `1e-5 + 1e-5·|ref|`；窗口滑动不改变已缓存 `m^ℓ_t`；每步时间核成本随 s+W 线性。

预注册判读（选点 EMA 等会话 R²，1,011 面）：

| 结果 | 规则 | 动作 |
|---|---|---|
| 统一 | U ≥ max(A,B) − 0.010 | U 为家族默认；M1 补 s∈{1,8} 确认；H1 待前端可学后迁移 |
| 机制 | A−B ≥ 0.010 且 U−B ≥ ½(A−B) | 出生冻结找回了 A 的可缓存部分 |
| 留 B | A−B < 0.010 且 U−B < 0.010 | M2 上互读不值一个新名字；B 就是统一核 |
| 升级 | A ≥ B+0.015 且 A ≥ U+0.015 | 需要短窗重算键；开 HybridDense，不再扩 U |
| 杀 U | U ≤ B − 0.010 | 局部记忆有害；不带去 H1 |

M1 的 −0.004 低于这些边界是刻意的：若 M2 的 A/B 差也这么小，诚实结论是 B 已统一，s 是文档化的空拨盘。
