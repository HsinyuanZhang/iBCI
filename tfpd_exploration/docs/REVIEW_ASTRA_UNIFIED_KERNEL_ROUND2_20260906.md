## 2. 关键合同冲突：前端 token 本身会在左边界变化

当前前端是 causal Conv k=5。对当前窗 `[a,T]`，最左 token 的卷积输入为
`[0,0,0,0,x_a]`；同一物理 bin 在更早时刻出生时，输入可能为
`[x_(a-4),...,x_a]`。两者一般不同。

所以现有精确流式实现每次滑动都重算前端位置 `0,1,2,3,W-1`。这不是一个
可随意移除的工程补丁，而是严格有限窗定义的一部分。

代码依据：

- [实际 k=5 前端](../src/two_mainlines_long_v1/decoder/h1_temporal.py)。
- [有限窗五位置修复](../src/two_mainlines_long_v1/latency_opt_v2/exact_window.py)。
- [M2 实际运行时同样修复边界](../src/m2_runtime_v3/runtime.py)。
- [QueryMemoryCache 验证并更新 changed indices](../src/two_mainlines_long_v1/current_query_v2/core.py)。

因此，不能只把缓存里的 `z` 换成 contextualized `m`，就沿用现有精确缓存证明。
若选择严格 W，局部记忆的边界变化会随层向右传播；若选择永久冻结，则允许
模型保留当前原始 W 窗以前的信息。二者都是可以研究的模型，但不是同一合同。

设 L=4，局部跨度 s，`a=T-W+1`。按交接稿的公式，最终 query 读取最深
`m^3`，出生冻结版本可依赖早至 `a-3(s-1)-4` 的原始输入；其中4来自前端。
例如 W=50、s=50 时，名义50-token查询窗可实际包含201个原始 bin 的依赖范围。
这不是未来信息泄漏，但不再是当前的严格50-bin算子，训练时的随机 W 窗也不能
不加说明地代表这种部署状态。

严格窗候选则需修复边界依赖锥，不能只算一个新 token。一般性的受影响边界
上界随层从4扩展到 `min(W,4+ell*(s-1))`；还要计算新 token。准确开销须由
已实现的依赖图、投影次数和端到端计时验证，不采纳“约400倍”作为执行预算。

## 3. 三项算子表述必须修正

1. **s=1 可以精确包含 B，但要靠明示旁路合同。** 将所有 `m^ell:=z` 并调用
   同一 QueryAge 查询路径，同时保留当前窗的前端边界修复，才有现有 B 的等价。
   普通跨度1的 attention block 仍有投影、残差和 FFN，并不自然成为恒等映射。
   “逐字节”与“元素容差通过”也要分开记录，不能混作一个指标。
2. **s=W 加重算仍不自动等于 A。** 当前 A 有窗口内正弦 PE，U 使用相对 age，
   B 的 query/memory Norm 也与 A 的参数化不同。恢复全跨度只恢复互读范围，
   不恢复完整算子。只允许在相同 PE/Norm/投影/残差条件下证明 exact-E 等价。
3. **稿件计算了未被查询使用的 m4。** 其 q1..q4 读取 m0..m3。必须明确是删去
   无用途的 m4，还是改查询路径；不能将前者的开销与后者的感受野混算。

补充：16档分段常数 age 表不严格包含逐年龄变化的 ALiBi 线性斜率族；“严格更强”
的集合包含说法不成立。这不构成现在启动 ALiBi 的理由，只修正论证。

## 4. 接受的实验纪律，以及需要保留的不确定性

接受：先完成 M2 B；若另做 A/B/U，配方必须一致；不在同名 QueryAge 中更换
age 规则；不迁移 A 权重冒充 U；不以官方/hidden 结果选点；不用 M1 的局部
成功代替 M2/H1 证据；不并行打开多个相邻新核。

以下归因暂不接受为事实：

- “H1 洞一定在前端/冷启动、而不在时间核”。现有干预确实显示 prefix 的收益
  主要集中在冷历史，dense 没补完整历史差距；这仍不能排除 temporal、训练配方、
  泛化和前端的交互。H1 仍可评估预注册的算子迁移，只不能根据结果临时改选择规则。
- “H1 容量门槛不用 EMA/prefix，所以是配方对照”。现有 H1 A 的260→1040容量
  门槛同样为 LR2e-4、micro4/effective16、无 dropout/EMA/prefix；新门槛对齐的是
  那个学习能力筛查，不是 M1/M2 的正式训练。容量门槛和正式质量实验是两件事。
- “M1/M2 都已经使用 prefix”。当前 M1 正式 `train_p1` 使用 EMA 和 whole-unit
  dropout，没有新 M2 的随机历史 prefix 变换。不能用这句话要求三任务形式统一。
- “蒸馏追不上就证明独立 memory 无法表达互读”。失败仍可能来自优化、容量与预算；
  可作为诊断证据，不能当表达能力不可能性的证明。当前不优先增加蒸馏实验。

## 5. 下一格如何判读，而不是先宣布统一

优先完成当前 B 的质量与实际权重运行时证据。需要新的机制比较时，先冻结
上述严格有限窗 U 的完整定义及 CPU 合同，再决定是否开同配方 M2 FLAT 筛查。
该筛查不替代最终 FLAT/ROUTE 成对验收，也不把开发面选出的核称为未触碰泛化。

源 minival 的 `.01` 差值只能决定是否值得下一步投入。必须报告逐会话、等会话、
pooled 指标及配对不确定性；不把不同任务、不同配方或 pooled/等会话结果混在
一列。接近边界不能只凭单个 seed 的点估计称为非劣。阈值规则还需改为互斥，
避免“统一”和“杀 U”在边界处同时成立。

只有在 M1/M2/H1 各自通过质量保留与实际公开调用性能验证后，才把一个算子或
同一定义的 s 参数族称为统一主线。M2 内 U≈A/B，但全家仍低于 SPINT，并不能
完成用户的质量目标。H1 的空间配方差异仍须明列，时间统一不等于整网完全相同。

结论：**采纳“局部记忆是有条件后备”的方向，拒绝未经修正的永久冻结等价声明；
继续当前 QueryAge 收敛路线，不凭这份 REVIEW_ONLY 交接新增训练。**
